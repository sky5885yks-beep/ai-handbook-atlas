# 设计文档：AI Handbook 导航地图

- 版本：v1.0
- 日期：2026-11-23
- 在线：<https://37lf4zrsvx0csetmpgj.traesite.cn/>（仅自己可见）

---

## 1. 定位

### 1.1 问题

GitHub 上的 AI handbook 很多，但存在三个问题：

- 分散：官方手册、社区教程、Infra 笔记、安全指南混在一起；
- 质量差异大：star 高不等于持续维护；
- 缺少路径：知道有哪些仓库，但不知道按什么顺序读。

### 1.2 方案

把仓库按“生态层级”铺成地图，再用“推荐路线”把节点串起来。用户既可以按层浏览，也可以按目标走一条路线。

一句话：

> 把散落的 AI 手册画成一张可走的地图。

### 1.3 目标用户

- 想系统入门 AI/LLM 的学习者；
- 想快速上手 Agent 的开发者；
- 关注推理/Infra、安全红队、具身语音的工程师；
- 准备 AI 岗位面试的求职者。

### 1.4 非目标

- 不做仓库全量索引；
- 不做实时 star 排行；
- 不做课程内容托管；
- 不做社区/评论。

## 2. 信息架构

```
Header（品牌 / 搜索）
  └─ Hero（主张 / 统计 / 推荐路线按钮）
      └─ Map（6 个生态层级，每层若干节点）
          └─ Aside（节点详情 / 图例 / 使用提示）
Footer（数据来源 / 快照日期）
```

设计意图：

- 层级负责“分类”，路线负责“顺序”；
- 地图是主视图，详情面板不打断浏览；
- 图例解释状态点与徽章，降低理解成本；
- 页脚标明快照，提醒数据会过期。

## 3. 数据模型

### 3.1 层级 `BANDS`

```js
{ id: "official", no: "01", title: "官方 / 机构出品", desc: "出版社、云厂商、框架团队写的第一手实践，权威性最高。", official: true }
```

6 个层级与节点数：

| id | 标题 | 节点数 |
| --- | --- | --- |
| `official` | 官方 / 机构出品 | 9 |
| `community` | 社区体系化教程 | 10 |
| `engine` | 工程 · 推理 · Infra | 7 |
| `security` | 安全 · 红队 | 2 |
| `embodied` | 具身 · 语音 | 3 |
| `career` | 求职 · 面试 | 3 |

### 3.2 仓库 `REPOS`

```js
{
  id: "huggingface/alignment-handbook",
  f: "huggingface/alignment-handbook",
  s: 5720,
  d: "2026-09-23",
  l: "Apache-2.0",
  st: "active",
  band: "official",
  t: "Hugging Face 官方模型对齐手册：SFT / DPO / ORPO 配方与 TRL 可复现代码。",
  n: ""
}
```

字段说明：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | string | `owner/repo`，唯一 |
| `f` | string | 展示用全名 |
| `s` | number | star 快照 |
| `d` | string | 最近推送日期 |
| `l` | string | License |
| `st` | string | 维护状态 |
| `band` | string | 所属层级 |
| `t` | string | 一句话定位 |
| `n` | string | 备注/提示，可为空 |

### 3.3 状态

| 状态 | 含义 | 数量 |
| --- | --- | --- |
| `active` | 近期持续更新 | 24 |
| `slow` | 更新变慢 | 7 |
| `stale` | 长期未更新 | 2 |
| `caution` | 需谨慎（质量/维护/内容风险） | 1 |

状态是启发式判断，不是官方结论。

### 3.4 推荐路线 `ROUTES`

| id | 名称 | 说明 |
| --- | --- | --- |
| `start` | 系统入门 | 从官方手册到工程手册的入门路径 |
| `agent` | 上手 Agent | 直接做 Agent 的路径 |
| `infra` | 啃推理与 Infra | 推理引擎、容量规划、算子 |
| `safe` | 安全与红队 | 安全测试与攻防 |
| `career` | 求职准备 | 面试与岗位知识 |

每条路线是一组仓库 `id`，点击后过滤并高亮对应节点。

## 4. 视觉设计

### 4.1 色彩

| 变量 | 值 | 用途 |
| --- | --- | --- |
| `--paper` | `#ffffff` | 页面底色 |
| `--surface-sunk` | `#f6f6f4` | 次级背景 |
| `--line` | `#e7e7e5` | 分隔线 |
| `--line-strong` | `#d4d4d1` | 强调边框 |
| `--ink` | `#1d1d1b` | 主文字 |
| `--ink-2` | `#5c5b55` | 次文字 |
| `--ink-3` | `#8a887f` | 弱文字 |
| `--accent` | `#1f6b5a` | 主强调（深绿） |
| `--accent-soft` | `#e3efea` | 强调底色 |
| `--key` | `#9a5a08` | 次强调（棕金） |
| `--key-soft` | `#f6ecdc` | 次强调底色 |
| `--danger` | `#b3261e` | 风险状态 |

与创作者站点共用一套“纸张 + 墨水”的设计语言，形成系列感。

### 4.2 字体

- 正文：`Noto Sans SC / PingFang SC / Microsoft YaHei / system-ui`
- 标题：`Noto Serif SC / Songti SC / Source Han Serif SC / Georgia`
- 等宽：`JetBrains Mono / SF Mono / Menlo`

### 4.3 节点视觉

- 节点卡片：1px 边框、白底、hover 提升；
- 状态点：`active` 绿、`slow` 黄、`stale` 灰、`caution` 红；
- 徽章：`official` 表示官方出品，`route` 表示当前路线命中；
- 路线高亮：`route-on` 提升边框与底色，弱化非路线节点。

### 4.4 响应式

- `>1080px`：主地图 + 右侧 sticky 详情面板；
- `≤1080px`：取消 sticky，详情移到下方；
- `≤680px`：搜索、hero、统计、层级与节点宽度重排；
- `prefers-reduced-motion`：关闭过渡。

## 5. 交互设计

| 交互 | 触发 | 行为 |
| --- | --- | --- |
| 搜索 | 输入框 `input` | 匹配仓库名、描述、层级 |
| 路线 | 点击路线按钮 | 切换 `activeRoute`，过滤并高亮 |
| 节点详情 | 点击节点 | 右侧面板展示定位、状态、License |
| 清除筛选 | 再次点击路线/清空搜索 | 恢复全量 |
| 图例 | 固定展示 | 解释状态点与徽章 |
| 移动端 | 断点重排 | 详情面板下移 |

关键实现：`applyFilters()` 统一处理搜索与路线，`select()` 负责详情面板。

## 6. 技术实现

- 单文件 `index.html`：内联 CSS 与 JS，零依赖、零构建；
- 数据硬编码，加载即渲染；
- 无后端、无外部 API、无 CDN；
- 地图用普通 DOM 分区 + 节点卡片实现，没有引入图形库；
- 部署为静态文件，由 TraeSite 托管。

### 6.1 为什么不用图形库

- 节点只有 34 个，按层级分组比自由力导向图更可读；
- DOM 节点天然支持文本、徽章、hover 与响应式；
- 避免引入 D3/Cytoscape 的体积与学习成本。

代价是“地图感”偏弱，更接近分层目录；这是有意的取舍。

---

## 7. 可访问性

- 搜索框有可读 label；
- 节点可点击，选中态有视觉反馈；
- 图例使用文字 + 颜色双编码；
- 支持 `prefers-reduced-motion`；
- 详情面板有明确标题。

待补：节点键盘操作（Enter/Space）、`aria-selected`、路线按钮的 `aria-pressed`、移动端详情抽屉的焦点管理。

## 8. 数据维护流程

1. 确认仓库属于“成体系的 AI/LLM/Agent 手册”；
2. 查 GitHub 仓库，记录 star、最近推送、License；
3. 归入最合适的 `band`，写一句话定位；
4. 判断状态：`active/slow/stale/caution`；
5. 如需进入路线，加入对应 `ROUTES.ids`；
6. 更新页脚快照；
7. 运行 `python scripts/check_site.py`；
8. 本地预览搜索、路线、详情、移动端；
9. 重新部署。

## 9. 已知问题

| 问题 | 影响 | 计划 |
| --- | --- | --- |
| star/最近推送是快照 | 会过期 | P1 提供刷新脚本 |
| 状态是启发式 | 可能误判 | P1 记录判断规则与日期 |
| 数据硬编码 | 难校验、易冲突 | P1 抽到 `data/repos.json` |
| 链接可能失效 | 点击 404 | P1 链接检查 |
| 节点键盘可达性不足 | 无障碍 | P1 改为 button + ARIA |
| 移动端详情面板较长 | 浏览成本 | P2 改抽屉 |

## 10. 路线图

### P1：可维护性

- 数据抽离为 JSON；
- 构建脚本注入数据；
- star/最近推送刷新脚本；
- 链接检查与状态规则文档化；
- 节点键盘与 ARIA 完善。

### P2：体验

- URL hash 深链到节点；
- 移动端详情抽屉；
- 层级折叠；
- 路线进度标记（已读/未读，本地存储）。

### P3：平台化

- 与创作者图谱互相跳转；
- 仓库质量评分与更新时间趋势；
- 数据 API 化。

---

## 11. 风险与边界

- 非官方整理，与仓库作者无隶属关系；
- star 与状态仅作参考，不构成质量背书；
- License 以仓库为准，转载内容需遵守各自许可；
- 路线是主观推荐，不是唯一学习路径；
- 数据快照会过期，使用前应核对原仓库。

## 12. 决策记录

| 编号 | 决策 | 理由 | 代价 |
| --- | --- | --- | --- |
| ADR-001 | 单文件静态页 | 零构建、易部署、易备份 | 数据与视图耦合 |
| ADR-002 | 分层地图而非力导向图 | 34 个节点，分层更可读 | 视觉“地图感”弱 |
| ADR-003 | 路线与层级双维度 | 同时回答“有哪些”和“怎么读” | 数据需维护两份关系 |
| ADR-004 | 不接实时 GitHub API | 避免限流与密钥 | star 会过期 |
| ADR-005 | 状态用启发式 | 低成本提示维护情况 | 可能误判 |
